## Главные технические находки сессии (детали в docs/power-log.md)

- модальные выборы (раскопка, тройка, лавка) — канал
  `DebugPrintEntityChoices`/`SendChoices`, мимо стека блоков;
- магнетизм — механика `MODULAR` снапшота; полный борд не требует продажи;
- у заклинаний два CARDTYPE: руки — SPELL, витрины — BATTLEGROUND_SPELL
  (с живой ценой в COST — единственные карты магазина с ценой в логе);
- плейсхолдеры текстов `{0}..{3}` ↔ `TAG_SCRIPT_DATA_NUM_1..4`;
- заряды тёмного дара — NUM_2 на кнопке (3→0), после нуля кнопка живая;
- карты-смертники — энчант `TB_BaconShopBadsongE` + `NUM_TURNS_IN_HAND=1`;
- племя тринкета — тег `BACON_SUBSET_<RACE>` (имена = races снапшота);
- `CARDRACE` строками, `MECHANICAL` ≠ `MECH` снапшота — кандидат-источник
  состава племён партии, отложен с фактурой;
- на полном борде ценность кандидата считать против борда БЕЗ жертвы;
- порог заморозки от тира; племя без амальгам/одноимённых (`_G`!);
  в ход подъёма племя-заморозка молчит.

## Рабочий процесс, который сложился (закреплён в памяти)

1. Лог забирается сразу: `C:\Program Files (x86)\Hearthstone\Logs\<свежая
   сессия>\Power.log` → `data/logs-raw/` + `data/fixtures/partN/game.log`.
2. Каждая жалоба ВОСПРОИЗВОДИТСЯ пробой до правки: срезы лога по времени
   скриншота (`text.indexOf('D HH:MM:S')` → reduce) или прокруткой
   до предиката (reduceUntil в part11.test.ts). Часы на скриншоте —
   в левом нижнем углу; «ход» игрока может быть и нашим номером, и раундом.
3. Правка → юнит-тест в rules.test.ts + сквозной partN.test.ts
   + partN.expected.json (пометка «скриншот из чата» или «со слов») →
   полный прогон → docs + CLAUDE.md → мелкие коммиты.
4. Черновые пробы — в скретчпаде сессии, в git не идут.

## Если игрок пришёл с новой партией — с чего начать

Забрать свежий лог (см. процесс выше), написать пробу по описанным
моментам, воспроизвести каждый пункт до правки. Оверлей у игрока
пересобирается командой `npm run overlay`.
