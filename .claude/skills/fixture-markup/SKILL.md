# Как размечать новые фикстуры

Перенесено из корневого `CLAUDE.md` 20.09.2026: разметка случается, когда
приходит новая партия, а не каждую сессию, — поэтому порядок лежит здесь,
а в контексте остаётся одна строка описания.

Видео бесполезно — ассистент его не читает. Работает так:

1. Игрок делает **скриншоты** на разных ходах и кладёт их ФАЙЛАМИ
   в `data/screenshots/` с часами кадра в имени (`13-53-59.png`; в git
   не коммитятся). По картинке в переписке пиксели для разметки не берутся.
   **Номера `partN` игрок знать не может**: его назначает вырезка (шаг 2),
   а в одной сессии клиента партий бывает две — part64 и part65 приехали
   одним логом. Поэтому папка называется тем, что известно во время съёмки:
   датой и временем НАЧАЛА партии, `data/screenshots/2026-09-22_1454/`.
   Переименовывает её в `partN` тот, кто вырезал фикстуру. Кадры, брошенные
   плоско в `data/screenshots/`, тоже годятся: часы в имени важнее папки,
   именно они привязывают кадр к партии (`--frame`).
2. `npm run fixture:passport -- <сессия клиента> --frame=ЧЧ:ММ` называет
   партию кадра, режим, место и доиграна ли она; `--game=N --write=partN`
   вырезает партию в фикстуру байт в байт. Часы кадра — такая же проверка
   лога, как режим и `FINAL_GAMEOVER` (part49: кадры были из другой партии).
3. Кадр из середины хода воспроизводит `npm run fixture:at -- partN ЧЧ:ММ:СС`:
   состояние, действия игрока внутри минуты и советы теми же строками,
   что показывает оверлей, плюс отличие от точки решения того же хода.
4. Совпавшее идёт в `partN.expected.json` с пометкой `verifiedBy: скриншот`.

Точка решения — состояние ДО первой траты, а кадр почти всегда снят
в середине хода: сверять надо срезом `fixture:at`, а не точкой решения.
Проверять то, что от момента не зависит: состав, порядок, атаку, золото, тир.

Пометки в `expected.json` различаются по силе: `подтверждено человеком` —
игрок видел это своими глазами в игре; `скриншот` — сверено по картинке.
