# Статистика мест миньонов: помогает ли она оценивать покупку

Вопрос, отложенный в CLAUDE.md с формулировкой «вливать глобальные винрейты
миньонов в ценность покупки — значит смешать наш контекстный расчёт
с бесконтекстным средним; не делается без отдельного замера сверкой».
Здесь — этот замер.

**Предрегистрация написана и закоммичена ДО первого прогона симулятора.**
Всё, что ниже раздела «Предрегистрация», зафиксировано заранее; результаты
дописываются под ним и не меняют условий. Каждый повторный сквозной прогон
увеличивает счётчик в шапке результатов: множественные взгляды на одну
выборку удешевляют вывод, и цену видно.

## Предрегистрация (15.08.2026, до прогона)

### Данные

- **Источник:** `https://static.zerotoheroes.com/api/bgs/card-stats/mmr-100/last-patch/overview-from-hourly.gz.json`
  (`npm run update:cardstats`). Сегмент `mmr-100` обязателен: вариант без него
  отвечает 200, но это сумма пяти перекрывающихся корзин MMR — `dataPoints`
  ровно ×5, у BG20_100 `totalPlayed` 478 738 = 248 088 + 129 544 + 67 717 +
  29 510 + 3 879. Двойной счёт, а не другая популяция.
- **Снапшот:** 926 записей, `timePeriod: last-patch`, `lastUpdateDate`
  **2026-08-15T00:10:38.759Z**.
- **Поля записи:** `cardId`, `totalPlayed`, `averagePlacement`,
  `averagePlacementOther`, `turnStats[]`. Полей `dataPoints`, `pickRate`,
  `standardDeviation` — нет; порог малой выборки считается по `totalPlayed`.
  Золотых версий в источнике нет вовсе (агрегатор их отбрасывает).
- **`turnStats` не используется:** контрольная группа там вырождается
  (у Titus Rivendare на ходу 9 контроль из 66 партий против 77 303
  основной группы). Считаем только по верхнеуровневым полям.

### Величина

- `impact = averagePlacement − averagePlacementOther`. Место тем лучше, чем
  меньше, поэтому у сильной карты impact отрицателен.
- **Центрирование по тиру обязательно:** impact коллинеарен тиру
  (`r = −0.3212`, `R² = 0.1031`; групповые средние по тирам снимают 37.3%
  дисперсии). Без вычитания среднего по тиру свободный вес молча
  перекручивал бы наш `perTechLevel: 2`, и замер мерил бы подгонку веса
  тира, а не пользу статистики.
- `residual = impact − tierMean[tier]`;
  `statGain = clamp(−residual, ±cap)`.
- **Отбор:** миньоны пула (`isBaconPool && type === MINION && techLevel`)
  с `totalPlayed ≥ 500` (`MIN_DATA_POINTS`, общий порог с героями
  и тринкетами). Получилось **297 карт**.

Замеры снапшота (посчитаны до прогона, боевых исходов не касаются):

| величина | значение |
|---|---|
| карт со статистикой | 297 |
| σ(impact) сырое | 0.4524 |
| σ(residual) после центрирования | **0.3582** |
| доля дисперсии от тира | 37.3% |
| r(impact, techLevel) | −0.3212 (R² = 0.1031) |

### Вес — структурный, выведен до данных

`λ_struct = perTribeMate / σ_residual = 1.5 / 0.3582 = **4.188** очка
за место`.

Заявление обмена: **одна сигма остатка стоит ровно одного своего миньона
племени**. Это тот же приём, что `trinketPlacePerTribeMinion: 0.3`, где
курс — сигма выборки снапшота. Кап `±2σ = ±0.7164 места = ±3.00 очка`,
то есть слагаемое не может перевесить щит, `sellMargin` или бонус второй
копии — прецедент капа щита/вихря/перерождения телом (part7, цена промаха
50 п.п.).

**При принятии в правила пойдёт именно `λ_struct`, а не подобранное
перекрёстной проверкой значение.** Кросс-валидация служит проверкой, что
структурный курс не абсурден, — не источником числа.

### Куда входит слагаемое

**Только в ранжирование покупок между собой. В `minionValue.total` — нет.**

Это инженерное решение, а не осторожность: `total` читают правила реролла,
заморозки, продажи, выбор жертвы `weakestOwn`, отбраковка на полном борде
(`replacing.total <= victim.value + sellMargin`) и сравнение «подъём против
лучшей покупки». Войди статистика в `total` — изменился бы сам состав
кандидатов и борды, которые идут в симулятор, и парность замера пропала бы.
При ранжировании-только борд каждого кандидата от веса не зависит, поэтому
**исходы считаются один раз, а любой вес проверяется по сохранённому дампу
без единой новой симуляции**, и на ходах без смены выбора разность ровно
ноль, а не «в пределах шума».

Плата объявлена: правило по построению не может спасти кандидата,
отбракованного на полном борде, сменить жертву продажи или поучаствовать
в споре «покупка против подъёма».

### Процедура

1. **Дамп.** Фикстуры — ровно `FIXTURES` из `validate.ts`: part4…part16,
   13 партий билда 248348. Старые билды не добавляются никогда (на 246003
   калибровка ухудшалась 3.9 → 9.0 п.п. без единой правки кода).
   Точка решения — как у `readTavernTurns`. Противник — борд, **фактически
   вышедший в бой хода `turn+1`** (последний виденный борд запрещён: все
   сравнения выходили 100:0 при нулевом разбросе).
2. **Симуляции.** 4000 на кандидата (вдвое против сверки: ловим слабую
   связь). Зерно `FNV-1a(fixture|turn|candIndex|cardId|entityId)` через
   пакетный `withSeededRandom` — подмена `Math.random` с версии 1.1.737
   не действует. Зёрна у кандидатов РАЗНЫЕ (общие случайные числа проекту
   уже мерились: 0.9×, выигрыша нет) и одинаковые между прогонами, поэтому
   дамп воспроизводим побитно. Исход `= wonPercent + tiedPercent/2`.
3. **Строка дампа** (JSONL, вне git): фикстура, ход, индекс кандидата,
   карта, тир, золотой, цена, все 11 слагаемых `ValueBreakdown` и `total`,
   исход, признак «выбор эвристики», и статистика: `placement`, `other`,
   `impact`, `residual`, `statGain`, `totalPlayed`.
4. **Проверки годности — читаются ДО главных чисел:**
   - *шлюз методики*: пересчитанные по дампу совпадение и средняя цена при
     λ=0 обязаны лечь на опубликованные 80% и 3.02 п.п. (±5 п.п. и ±0.5 п.п.);
   - *воспроизводимость*: дамп по одной партии дважды — побайтно равен;
   - *положительный контроль*: переранжирование с удвоенным `perStatPoint`
     обязано сменить хотя бы один выбор и дать ненулевую Δ;
   - *покрытие*: доля кандидатов со статистикой ≥ 70%.
5. **Связь** (ноль симуляций). Всё центрируется **внутри хода** — иначе
   мерится «ход 3 против хода 15». Спирмен: **V1** — `statGain` против
   остатка исхода после `total`; **V2** — после всех 11 слагаемых (строгий
   тест на дублирование); **V3** — после `tech + stats`.
   **Нуль — перестановка `statGain` между картами ОДНОГО ТИРА, 10 000 штук**:
   такой нуль сохраняет всё, что идёт от тира, и ломает только
   карто-специфическое; перестановка на уровне карт, а не строк, заодно
   лечит зависимость строк (одна карта встречается в нескольких ходах).
6. **λ-свип** (ноль симуляций): λ ∈ {0, 1, 2, 3, 4.188, 6, 8, 12},
   парная `Δcost_i = cost_i(0) − cost_i(λ)`; на ходах без смены выбора
   строго 0. Печатается m — число ходов со сменой выбора.
7. **Неопределённость — кластерами по партиям, не по ходам**: бутстрап
   2000 ресэмплов 13 фикстур с возвращением → 90% ДИ; leave-one-game-out
   по каждой из 13; LOFO-CV (λ выбирается на 12 партиях, оценивается на 13-й).
8. **Отрицательный контроль конвейера:** `statGain` перемешивается внутри
   тира, весь конвейер прогоняется заново. Если перемешанная статистика
   проходит критерий — побеждает процедура, а не данные, и прогон
   объявляется недействительным.
9. **Устойчивость:** порог выборки 5000 вместо 500; сырой `averagePlacement`
   вместо impact.

### Критерий решения (зафиксирован заранее)

Шум при 4000 симуляций: σ одной оценки ≤ √(0.25/4000)·100 = **0.79 п.п.**,
σ разности двух кандидатов = √2·0.79 = **1.12 п.п.** Парная схема даёт вклад
Монте-Карло в Δcost `SE = 1.12·√m/108` — **0.05–0.11 п.п.** Связывающая
неопределённость — не симулятор, а 108 ходов.

**ПРИНЯТЬ — только при выполнении ВСЕХ пунктов:**

1. все четыре проверки годности пройдены, покрытие ≥ 70%;
2. **V2 ≥ +0.15** при одностороннем **p ≤ 0.01** по внутритировым
   перестановкам (df ≈ 297, SE(r) ≈ 0.058, то есть 0.15 ≈ 2.6σ);
3. не дублирование: `R²(statGain ~ 11 слагаемых) < 0.8` и `V3 ≥ 0.5·V1`;
4. **Δcost(λ_struct) ≥ +0.5 п.п.**, нижняя граница 90% кластерного
   бутстрапа > 0, положительна при выбрасывании любой из 13 партий;
5. знак Δcost одинаков на всей полосе λ ∈ [2, 8];
6. LOFO-CV даёт Δcost > 0, знак одинаков во всех 13 фолдах, значение выше
   99-го перцентиля перестановочного нуля всего конвейера;
7. на решающем подмножестве (spread > 3 при λ=0) средняя парная Δ ≥ **−1.0
   п.п.**, нет двух и более разгромных ходов (Δᵢ < −15 п.п.) при одном
   симметричном выигрыше;
8. при `minPlayed = 5000` знак Δcost сохраняется.

Порог 0.5 п.п. выбран так, чтобы эффект был виден и старым способом: он
в 5–10 раз выше пола Монте-Карло и ровно накрывает полосу, которую проект
уже публично называл шумом (сдвиги 0.1–0.5 п.п. у правок JeefHS
и `perNamedCardMate`).

**ОТВЕРГНУТЬ — достаточно любого:** V2 < 0.10 или p > 0.05; V2 ≈ 0 при
заметной V1 (связь целиком объясняется перевзвешиванием того, что у нас уже
есть); реальное значение накрыто внутритировым нулём (значит это тир);
Δcost(λ_struct) ≤ +0.2 п.п. или отрицательна; верхняя граница бутстрапа < 0;
знак скачет между фолдами; на решающем подмножестве Δ < −1.0 п.п.

**НЕ ДОКАЗАНО** — всё промежуточное (V2 в 0.10–0.15, Δcost в 0.2–0.5 п.п.).
Это **не** «принять с оговоркой»: умолчание проекта — не добавлять. Числа
всё равно записываются.

**ПРОГОН НЕДЕЙСТВИТЕЛЕН**, если перемешанная внутри тира статистика проходит
пункт 4, или шлюз методики не сошёлся, или дамп невоспроизводим.

### Заранее объявленный масштаб

При V2 = 0.15 и связи нашей оценки с исходом ρ₀ ≈ 0.3 совокупная связь
растёт с 0.300 до ≈0.332, а выигрыш выбора из ~3.75 кандидатов —
порядка **0.1 п.п.**: статистически различимо, продуктово невидимо. Чтобы
Δcost дотянул до 0.5 п.п., нужна V2 порядка 0.30. Поэтому V2 отвечает
на «сигнал вообще есть», а Δcost — на «сигнал стоит правила».

### Чего этот замер не докажет

1. **Мишени разные.** Статистика предсказывает финальное место за партию,
   мерка — исход ближайшего боя. Карта, сильная экономикой или заделом
   на три хода (River Skipper и родня), окажется здесь шумом честно
   и неверно. Отрицательный результат читается строго как «сигнала
   для ближайшего боя нет».
2. **Разрешающая способность ≈ 0.5 п.п.** и упирается в 108 ходов текущего
   патча, а не в число симуляций. Лечится новыми партиями своего билда
   (`data/dataset/` их копит с 15.08), но не добавлением старых фикстур.
3. **Даже impact не причинный:** контроль — партии без этой карты, а не
   «та же позиция, другая покупка». Смещение выживания остаётся
   и после центрирования.
4. **Двойной счёт неотделим.** Сильная карта уже получает очки за племя,
   текст, имя и боевой эффект. Положительная Δ равно совместима
   с «статистика знает то, чего не знают правила» и с «наши веса чуть
   занижены».
5. **Отбор кандидатов идёт нашей же шкалой:** вопрос «находит ли статистика
   то, что мы пропускаем» задаётся на множестве, уже профильтрованном тем,
   что мы не пропускаем.
6. **Покрытие рваное:** золотые исключены источником по построению, им
   подставляется 0 = «средняя карта». Это подставленное значение, а не факт.
7. **Борд кандидата упрощён** (миньон в конец, без поиска расстановки
   и без баффов соседям конца хода), тогда как статистика карты уже
   содержит её позиционную ценность — систематическое занижение.

## Результаты (15.08.2026)

**Сквозных прогонов: 1.** Условия приёмки не менялись после того, как числа
были увидены. Отчёт `npm run analyze:cardstats` дорабатывался после прогона
дважды — но только в части ПЕЧАТИ (добавлены полоса нуля для Δcost,
минимальный различимый эффект, честная метрика совпадения и чувствительность
к первому ходу); ни одного порога приёмки это не коснулось, вердикт
не изменился.

### Вердикт: ОТВЕРГНУТЬ — слагаемое не вносится

По предрегистрированной ветке: `V2 = −0.078 < 0.10` при `p = 0.87`, то есть
сигнала требуемой величины сверх наших одиннадцати признаков не обнаружено.

**Читать как «польза не показана», а не «статистика вредит».** Отрицательные
числа в таблице ниже почти целиком объясняются устройством самой мерки,
и состязательная проверка (четыре независимых скептика, каждый со своим
кодом) это подтвердила.

### Годность прогона — пройдена

| проверка | результат |
|---|---|
| шлюз методики | совпадение 80% и цена 2.96 п.п. против опубликованных 80% и 3.02 — дамп меряет то же, что `validate:tavern` |
| воспроизводимость | два прогона по part5 побайтно равны |
| положительный контроль | удвоенный вес статов сменил выбор на 14 ходах, Δcost +0.52 п.п. — конвейер способен увидеть пользу |
| покрытие | 98.5% кандидатов со статистикой (399 из 405); без данных только 6 золотых |

### Главное: сигнала сверх наших признаков нет

| величина | значение | порог |
|---|---|---|
| ρ₀ (наш `total` ↔ исход, внутри хода) | 0.2515 | — |
| V1 (после `total`) | −0.1067 | — |
| **V2 (после всех 11 слагаемых)** | **−0.0782** | ≥ +0.15 ✗ |
| V3 (после тира и статов) | +0.0341 | — |
| p(V2), внутритировые перестановки | 0.87 | ≤ 0.01 ✗ |
| R²(statGain ~ 11 слагаемых) | 0.183 | < 0.8 ✓ |

Ветка V2 разрешение имела: против истинной связи 0.15–0.20 её мощность
62–87%. Она искала и не нашла — на это вывод и опирается.

### Ветка «цена выбора» своего порога не разрешала

| λ | смен выбора | совп. (первый макс.) | совп. (любой макс.) | Δcost |
|---|---|---|---|---|
| 0 | 0 | 80% | 80% | +0.00 |
| 2.00 | 14 | 69% | 78% | −0.53 |
| **4.19** | 25 | 64% | **78%** | **−1.16** |
| 8.00 | 38 | 53% | 73% | −2.08 |
| 12.00 | 45 | 49% | 72% | −2.11 |

Четыре причины, почему из этих чисел нельзя делать вывод «вредит»:

1. **Нулевая точка Δcost отрицательна по построению.** Советник при λ=0
   угадывает лучшего в 80% ходов; возмущение такого выбора ЛЮБЫМ
   неинформативным довеском в среднем портит его. Полоса перемешанной
   внутри тира статистики: 5-й перцентиль **−1.20**, медиана −0.07,
   95-й +0.73. Настоящая −1.16 — это **5.3-й перцентиль нуля**, то есть
   на его границе, а не за ней; 94.7% перемешанных вариантов не хуже
   настоящего.
2. **Эффективных наблюдений 10, а не 108.** У 58 ходов исходы всех
   кандидатов тождественны (выбор не решает ничего), ещё часть смен
   не меняет исхода. SD парных разностей 8.07, SE среднего 0.78 →
   **минимальный различимый эффект ≈ 2.17 п.п. против порога приёмки
   0.50**. Эта ветка почти не могла сказать «принять» ни при какой правде —
   методическая ошибка предрегистрации, а не свойство данных.
3. **Вся величина создана первым ходом.** Бой хода 1 идёт 1×1, исходы
   насыщены (0/25/50/100), разброс 37.5 п.п. против 6.7 на остальных ходах.
   **Без хода 1 Δcost = +0.27 п.п.** (и это тоже не довод «за»: нуль без
   хода 1 сам около +0.4).
4. **Падение совпадения преувеличено вдвое.** Ничьих за первое место 66
   из 108, и счёт «по первому максимуму» бесплатно награждает исходный
   порядок. По честной метрике «попал в любой максимум» падение
   с 80% до 78%, а не до 64%.

Кросс-валидация независимо согласилась: **LOFO-CV выбрала λ=0 в 12 фолдах
из 13** — даже когда весу разрешили подбираться по данным, данные ответили
«не нужен».

### Почему знак всё-таки отрицательный

Помимо механики мерки, работает предрегистрированная оговорка «мишени
разные», и она видна поимённо. Связь `statGain` с суммой статов кандидата
отрицательна (−0.169 по всем ходам, −0.39 на ходу 1): статистика ставит
масштабирование и позднюю выплату выше немедленного тела. Все пять смен
выбора на первом ходу — ровно такие: Glim Guardian (100% боя) → Buzzing
Vermin (50%), Tusked Camper с немедленными статами → Fleeing Fugitive,
Tusked Camper → River Skipper (экономика). Глобальное место платит за задел
на партию, наша мерка — за ближайший бой.

### Что сделано с результатом

- **Слагаемое в советник не вносится.** Снапшот статистики карт в git
  не кладётся; `npm run update:cardstats` остаётся инструментом замера.
- **Рантайм не тронут:** `cardStats.ts` лежит отдельно от `bgStats.ts`
  и на пути советника не стоит; `minionValue` и все правила побитово
  прежние.
- **Дамп сохранён активом** (`data/dataset/cardstats-dump.jsonl`, 405 строк
  с одиннадцатью слагаемыми и исходом боя). Любая будущая гипотеза
  «добавляет ли признак X сигнал к покупке» проверяется по нему за секунды
  и без единой симуляции.

### Уроки для следующих замеров

1. **У Δcost нулевая точка отрицательна** — сравнивать его можно только
   с полосой перестановок, и печатать её обязательно рядом.
2. **Ход 1 — другой режим, а не выброс** (бой 1×1, лотерейные исходы);
   обращение с ним объявлять заранее.
3. **Порог приёмки сверять с МРЭ ДО прогона.** Порог 0.5 п.п. при МРЭ
   2.17 — ветка была мертворождённой.
4. **Совпадение считать «попал в любой максимум»**: ничьих за первое место
   больше половины.
5. **Эффективный размер выборки — десятки решений, а не 108 ходов.**
   Повторять замер имеет смысл на НОВЫХ партиях своего билда
   (`data/dataset/` их копит), а не подкруткой параметров на этой же выборке.
