# Фаза 6, шаг первый: предсказание финального места

Задача из ТЗ: «предсказание финального места по `GameState` на ходу N».
ТЗ сознательно её не детализирует — детализация здесь. Это ПРОГНОЗ, а не
советник: модель не говорит «что делать», она говорит «куда идёт партия».
В рантайм (строку оверлея) прогноз попадает только по предрегистрированному
критерию ниже; умолчание проекта — не добавлять.

**Предрегистрация написана и закоммичена ДО первого прогона оценки.**
Всё, что ниже раздела «Предрегистрация», зафиксировано заранее; результаты
дописываются под ним и не меняют условий. Повторный сквозной прогон
увеличивает счётчик в шапке результатов. Предрегистрация прошла
состязательную проверку (три независимых скептика: статистик, хранитель
уроков cardstats, код-ревьюер; каждая находка проверялась адверсариально)
— восемь находок внесены правками ДО прогона, в том числе два разворота
критерия; отклонённые записаны в журнале проверки.

## Почему сейчас и почему так скромно

Датасет копится с 15.08 (`data/dataset/`, живой режим плюс
`dataset:backfill`), и в нём **23 уникальные партии** билда 248348 —
это и есть вся выборка. 23 независимых исхода не оправдывают ничего
сложнее линейной модели с горсткой признаков: бустинг и нейросети на такой
выборке выучат имена партий, а не игру. Ценность шага — не «внедрить ML»,
а поставить измерительный прибор: загрузка с дедупом, признаки, честная
кросс-валидация по партиям и записанный вердикт, который перезапускается
одной командой по мере роста датасета.

### Признаки — 7 штук, только «свои», из любого чекпойнта

| # | признак | источник | пропуск → |
|---|---|---|---|
| 1 | ход таверны | `tavernTurnOf(turn)` — шкала ходов, урок part20 | — |
| 2 | тир таверны | `techLevel` | — |
| 3 | здоровье с бронёй | `(hero.health − hero.damage) + hero.armor` | 0 (и при герое без прочитанного HEALTH) |

| 5 | лог-статы борда | `log1p(Σ(attack + health))` — рост статов по ходам экспоненциальный | 0 |
| 6 | прошлый бой | `wonLastCombat`: выигран +1, проигран −1, ещё ни одной победы 0 | 0 |

**Семантика пропуска «прошлого боя» — не «до первого боя».** Тег
`BACON_WON_LAST_COMBAT` пишется логом только при СМЕНЕ значения
(умолчание 0 не логируется; это же давно записано в
`battle/episodes.ts` — «приходит не с первого боя»), поэтому `null`
держится до ПЕРВОЙ ПОБЕДЫ: первый non-null во всех 28 записях — победа,
у backfill_part7 (7-е место, ни одной победы) поле null всю партию,
а значение −1 возможно только ПОСЛЕ первой победы. Пропуск ИНФОРМАТИВЕН
и коррелирует с целевой — поэтому признак №7, стандартный индикатор
информативного пропуска: без него кодировка «null → 0» систематически
приукрашивала бы проигрывающих. В выборке замера пропусков 65 из 277
(75 из 343 до дедупа).

В фактическом датасете место и здоровье есть во всех точках.

### Модель

Гребневая (ridge) линейная регрессия, чистый TS, закрытая форма:
- признаки стандартизуются по обучающему фолду (σ=0 → 1);
- целевая — финальное место как есть (1..8), интерсепт без штрафа;
- **λ = 1** на стандартизованных признаках — фиксирована заранее;
- предсказание зажимается в [1, 8];
- **обучение пулит точки 22 партий с равным весом ТОЧКИ** (длинная партия
  весит в подгонке больше) — сознательно: точка — самостоятельное
  наблюдение признаков, поздние точки существуют только у длинных партий,
  и взвешивание 1/n выморило бы позднюю область. Равный вес ПАРТИИ
  предрегистрирован для агрегации ОЦЕНКИ и для B0; взвешивание строк —
  кандидат на вторичную ветку при перезамере, не решает.

### Оценка — leave-one-game-out, кластер — партия

- 23 фолда: модель учится на 22 партиях, предсказывает все точки 23-й.
  Точки одной партии не разлучаются никогда — у них один исход.
- **MAE партии** = среднее |прогноз − место| по её точкам;
  **итог** = среднее MAE по партиям (равный вес партии, не точки:
  длинная партия — это доживший до конца, то есть хорошее место,
  и пул по точкам перекосил бы выборку к победителям).
- **Бейзлайны:**
  - **B0** — среднее место партий обучающего фолда (константа; среднее
    по партиям, не по точкам);
  - **B1** — текущее место из таблицы (`finalPlace` точки; нет → B0).
    Это главный соперник: игра сама показывает таблицу, и прогноз,
    не знающий больше таблицы, не стоит строки в оверлее;
  - **B2 — «сжатое место»**: та же ridge (λ=1, тот же LOGO), но
    с ЕДИНСТВЕННЫМ признаком текущего места. Отделяет «признаки борда,
    здоровья и тира несут сигнал» от «таблицу полезно просто сжать
    к среднему» — победа над B1 сама по себе их не различает.

### Критерий решения (зафиксирован заранее)

Основное число: `D_g = MAE_g(B1) − MAE_g(модель)` по каждой партии,
`D̄` — среднее по 23 партиям (положительное = модель лучше таблицы).

Полоса нуля: **sign-flip перестановки** — знак каждой `D_g` случаен,
10 000 повторов, ГПСЧ сеяный (`createRng(20260818)`), границы — 5-й
и 95-й перцентили перестановочных `D̄`. **МРЭ = 1.645 · SD(D_g)/√n**
(1.645 стандартных ошибки СРЕДНЕГО — формула записана однозначно,
двух чтений у неё нет) печатается рядом.

**Достижимость порога — посчитана ДО прогона и только по бейзлайнам**
(урок cardstats №3; модель не запускалась): средний |B1 − финал|
по корзинам ходов — 3.08 (ходы таверны 1–4), 2.31 (5–8), 1.43 (9–12),
0.68 (13+), у B1 есть запас во всех корзинах, кроме последней (22 точки
из 277); даже прогноз голым средним места на ранних точках даёт вклад
в `D̄` порядка 0.4. Порог 0.25 достижим — критерий не мертворождён.

- **ПРИНЯТЬ** (прогноз получает право на строку в оверлее — интеграция
  отдельным шагом со своими тестами) — только всё сразу:
  1. `D̄ ≥ 0.25` места (четверть места — минимум, различимый продуктово;
     порог задан на естественной смеси ходов партии — это и есть средний
     за партию выигрыш строки над чтением таблицы);
  2. `D̄` выше 95-го перцентиля полосы sign-flip;
  3. `D̄` выше МРЭ;
  4. средний MAE модели ниже среднего MAE B0 (по партиям, как в главной
     метрике).
- **ОТВЕРГНУТЬ** (как утверждение «таблица знает не меньше»): `D̄` НИЖЕ
  5-го перцентиля полосы sign-flip. Точечное `D̄ ≤ 0` внутри полосы —
  это НЕ ДОКАЗАНО, и формулировка результата — «польза не показана»,
  а не «таблица знает не меньше»: сравнивать точечную оценку с нулём
  нельзя (урок cardstats №1 — у таких разностей нулевая точка не ноль).
- **НЕ ДОКАЗАНО** — всё промежуточное. Это не «принять с оговоркой»:
  умолчание — не добавлять; перезамер при +10 новых партиях в датасете.

**Предобъявленная чувствительность — ранний режим** (урок cardstats №2:
режимно другой кусок выборки объявляется заранее). Ранние ходы — место
в таблице ещё лотерея, и именно там модель ОЖИДАЕМО бьёт B1. Рядом с `D̄`
печатается **D̄_late**: та же агрегация по партиям, но `D_g` считается
только по точкам с ходом таверны ≥ 5 (партии без таких точек выпадают
и называются вслух). Вердикт решает `D̄`; но если ПРИНЯТЬ достигнуто при
`D̄_late ≤ 0`, в результаты записывается «модель лучше таблицы только
до первых боёв», и право на строку в оверлее ограничивается ранними
ходами — расширение на всю партию требует отдельного перезамера.

**Предобъявленное чтение B2.** Если ПРИНЯТЬ достигнуто, но
`D̄₂ = MAE(B2) − MAE(модель)` по партиям ≤ 0, в результаты записывается:
«выигрыш у таблицы достигнут сжатием места к среднему, а не признаками
борда» — строка в оверлее остаётся (она честно лучше того, что игрок
читает с экрана), но интерпретация «признаки несут сигнал» не заявляется.

### Проверки годности — читаются ДО главных чисел

- **Отрицательный контроль конвейера:** финальные места ПЕРЕМЕШИВАЮТСЯ
  между партиями (сеяно, `createRng(20260819)`), и весь LOGO гоняется
  заново. На перемешанных местах модели учиться не на чем, и она обязана
  выйти НЕ лучше B0 своего прогона: если средний MAE модели там ниже
  среднего MAE B0 больше чем на 0.1 места — в конвейере утечка,
  и **прогон недействителен**. (Сравнение с B1 в контроле не годится:
  перемешивание ломает и B1 — текущее место указывает на СТАРЫЙ исход, —
  поэтому контролируется именно пара «модель против константы».)
- **Детерминизм:** обучение — закрытая форма без случайности, полоса
  и контроль — на сеяном ГПСЧ; два прогона обязаны дать одни числа.

### Вторичное — печатается, но НЕ решает

- MAE по корзинам ходов таверны (1–4, 5–8, 9–12, 13+), модель против B1
  и B0, по точкам; ожидание — модель выигрывает рано (место в таблице
  ещё лотерея), к поздним ходам сходится с B1.
- λ-свип {0, 0.3, 1, 3, 10} — устойчивость к регуляризации.
- Вариант нормировки признаков ВНУТРИ корзины ходов (z-score по корзине
  обучающего фолда; корзина, отсутствующая в обучающем фолде, нормируется
  глобальной статистикой фолда) — проверка нестационарности: hp=30
  на 3-м ходу и на 13-м — разные вещи.
- Доля точек с ошибкой ≤ 1 места — по всем точкам и по корзинам.
- Веса модели на всех 23 партиях — знаки и величины по именам признаков.

### Чего этот замер не докажет

1. **23 партии одного игрока одного билда.** Прогноз — про ЕГО стиль
   на ЭТОМ патче; переносимость не заявляется и не меряется.
2. **Поздние корзины селективны.** До 13-го хода таверны доживают
   в основном топ-места; сравнивать MAE МЕЖДУ корзинами нельзя, только
   модель против бейзлайна ВНУТРИ корзины.
3. **Модель информационно ⊇ B1** (текущее место — её признак). Выигрыш
   возможен только сверх таблицы; проигрыш — цена линейности
   и регуляризации. Оба исхода читаются как ответ на вопрос «есть ли
   в наших признаках что-то сверх таблицы», не больше, а разводка
   «сигнал признаков против сжатия к среднему» — только через B2.
4. **Точки одной партии зависимы** — поэтому кластеризация по партиям
   везде; эффективная выборка — 23, а не 277, и никакие «277 точек»
   в выводах не участвуют.
5. **Прогноз не причинен.** «Модель ждёт 5-е место» не значит «подъём
   таверны это исправит»; советов из прогноза не выводится.

## Результаты (18.08.2026)

**Сквозных прогонов: 2** — 18.08 на 23 партиях (ниже) и 28.08 на 33
(раздел «Перезамер 28.08.2026»). Условия приёмки не менялись после того,

### Вердикт: НЕ ДОКАЗАНО — прогноз в оверлей не вносится

Годность пройдена: отрицательный контроль на перемешанных местах дал
модель 1.934 против B0 1.834 — модель ХУЖЕ константы на чужих метках
(разность −0.100 при пороге утечки +0.1), конвейер чист. Дедуп сработал:
23 партии, 277 точек, пять дублей part17–part21 названы и отброшены.

| величина | значение | порог |
|---|---|---|
| MAE модели (LOGO, по партиям) | 1.874 | — |
| MAE B1 (таблица) | 2.129 | — |
| MAE B0 (среднее место) | **1.834** | модель обязана быть ниже ✗ |
| MAE B2 (сжатое место) | **1.823** | — |

### Чтение — три факта, каждый горше предыдущего

1. **Модель не лучше константы.** Лучший предиктор места из всех
   испробованных — «сжатое текущее место» (B2, 1.823), на волос впереди
   голого среднего (B0, 1.834); полная модель ХУЖЕ обоих (1.874).
   Выигрыш у таблицы (D̄ = +0.254) целиком создан сжатием шумного раннего
   места к среднему — ровно тот исход, который предобъявленное чтение B2
   и должно было отделить: «признаки борда несут сигнал» НЕ заявляется.
2. **После первых боёв таблица не хуже модели** (D̄_late = −0.152):
   по корзинам модель бьёт B1 только в ранних ходах (2.03 против 3.08
   на ходах 1–4), а в поздних проигрывает вчистую (1.18 против 0.68
   на 13+) — линейной модели не хватает взаимодействия «место × ход»,
   и предсказанный заранее ранний выигрыш не переносится никуда.
3. **МРЭ по факту 0.400 — выше продуктового порога 0.25.** При нынешнем
   разбросе D_g (SE 0.243 на 23 партиях) «ПРИНЯТЬ» требовал D̄ > 0.400:
   разрешающая способность выборки грубее продуктовой планки, и решает
   МРЭ, а не порог. Это было видно заранее лишь наполовину — достижимость
   D̄ = 0.25 мы проверили, а SD(D_g) до прогона не знали; урок остаётся.

Вторичное согласно: λ-свип монотонен В СТОРОНУ СЖАТИЯ (чем больше λ, тем
лучше — λ=10 даёт MAE 1.849 и D̄ 0.279: модель тем лучше, чем меньше
верит признакам), нормировка внутри корзин чуть лучше глобальной (1.853),
вывода не меняет. Веса единой модели буквально не интерпретируются —
признаки коллинеарны (hp падает, статы растут по ходу партии; частные
эффекты при удержанном месте меняют знак против интуиции).

### Почему так — и что это значит

Датасет — 23 партии ОДНОГО сильного игрока: распределение мест узкое
(среднее 3.65, восемь из 23 партий — топ-2), и константа на таком
распределении — грозный бейзлайн. Абсолютные «свои» признаки (hp, статы,
тир) место предсказывают слабо, потому что место — величина
ОТНОСИТЕЛЬНАЯ: 30 hp на ходе 9 — это хорошо или плохо в зависимости
от стола. Относительных признаков у датасета нет — `lobby` вошёл
в состояние 18.08, ПОСЛЕ всех записанных партий.

### Что сделано с результатом

## Дорожная карта: от прогноза места к «лучшим действиям» (19.08.2026)

Запрос игрока после первого замера: «хочу, чтобы модель на основе
победы/поражения училась лучшим действиям, которые приводят к победе,
и высчитывала лучшие ходы на данный момент». Честная декомпозиция:

**Классического RL здесь не будет** — учиться игрой нельзя: среды нет,
целиком партия Battlegrounds не симулируется (симулятор считает только
бои), а обучение на записанных партиях — это 23 исхода на тысячи
альтернатив действий. **«Лучшее действие из исходов» считается через
ценность состояния**: оценка действия = V(состояние после) − V(до),
и гипотетические состояния «после действия» советник УЖЕ строит — план
трат (`spend.ts`) живёт именно на них. Блокер — сам V: первый замер выше
показал, что на сегодняшних данных V хуже таблицы лидеров. Пока V слаб,
«лучшее действие для ближайшего боя» продолжает считать симулятор —
точный расчёт честнее обученного приближения.

Порядок шагов, каждый со своим замером:

1. **Журнал действий — СДЕЛАН 19.08.** «Какие действия ведут к победе»
   не выучить, не записывая действий, — а записи их не несли.
   `GameState.actions`: покупки и продажи с картой-целью (блоки PLAY
   на перетаскивателях, цель в `Target=[…]`), обновления витрины,
   подъёмы, заморозки, розыгрыши из руки, сила героя, тёмный дар,
   активации. Живой путь пишет журнал через то же состояние
   (эквивалентность живого и пакетного путей закрывает и его); досбор
   дописал журнал во все 28 лежащих записей — **4771 действие
   по 23 партиям**. Теперь ни одна сыгранная партия не теряет своих
   действий.
2. **Имитация покупок из выигранных партий** — ближайший кандидат
   на замер: парное ранжирование «что купил игрок против что было
   в витрине» на записанных действиях, сверка против советника
   (предсказывает ли модель выбор игрока лучше, чем он), LOGO
   по партиям, предрегистрация отдельным разделом ДО прогона.
   Отрицательный результат тоже ценен: он покажет, где игрок
   систематически расходится с советником.
3. **V(состояние) с относительными признаками** — перезамер основной
   ветки при +10 новых партиях, когда записи принесут `lobby`
   (hp против стола, тир против стола, место среди живых).
4. **ΔV-ранжирование действий** — только после того, как V пройдёт
   свой предрегистрированный критерий: ранжировать действия разностью
   слабого V значит выдавать шум за ML.

# Замер 2: имитация покупок игрока

**Предрегистрация написана и закоммичена ДО первого прогона (19.08.2026).**
Всё до раздела «Результаты замера 2» зафиксировано заранее.

## Вопрос

Предсказуем ли ВЫБОР ПОКУПКИ игрока сверх советника? Модель, обученная
на его же прошлых покупках, против верхней покупки `adviseTavern` —
то же определение «выбора эвристики», что в `validate:tavern`.
Это первый шаг ML, который именно ранжирует покупки; «лучшесть» здесь —
похожесть на игрока (средним местом 3.65), а не исход боя.

## Данные

- Вход: записи датасета с журналом действий (28 файлов, после дедупа
  23 партии; 4771 действие). Старые состояния нормализуются поверх
  `EMPTY_STATE` — полей, добавленных позже записи, у них нет.
- **Инстанс** — точка решения одного хода: кандидаты — МИНЬОНЫ витрины
  (их ≥ 2), метки — те из них, что куплены В ЭТОТ ход (join по `entityId`
  покупки из журнала); годен, если куплен хотя бы один и хотя бы один
  не куплен.
- Исключается и считается вслух: покупки заклинаний витрины, покупки
  вне показанной витрины (после обновления — выбор был из другой
  витрины), покупки на ходах БЕЗ точки решения (пришить не к чему),
  ходы «куплено всё» и «не куплено ничего из показанного».
- **Инстансы без выбора советника** (нет buy-совета с миньоном)
  исключаются ТОЛЬКО ИЗ ОЦЕНКИ — из всех метрик разом; в ОБУЧЕНИЕ они
  входят: меткам советник не нужен, и выбрасывать пары «куплен ×
  не куплен» из-за молчания бейзлайна значило бы обеднять модель
  решением, к ней не относящимся.
- Совпадение — ПО КАРТЕ (суффикс `_G` снят): две копии — один выбор,
  правило то же, что у `buyQuality`.
- **Фактические числа сборки** (посчитаны до прогона, модели
  не касаются): из 277 ходов — **154 инстанса** (121 ход без покупок
  из показанного, 1 «куплено всё», 1 «витрина из одного»); исключено
  покупок: заклинаний 70, вне показанной витрины 414 (игрок много
  крутит — эти выборы делались из невиданных нами витрин), на ходах
  без точки решения 41; инстансов без выбора советника 5; в среднем
  6.48 инстанса на партию. В 47 инстансах из 154 есть кандидаты
  с ТОЖДЕСТВЕННЫМИ векторами всех шести признаков, в 11 такая пара
  разрезана меткой — на это отвечает дробный hit ниже.

## Модель

- **6 признаков кандидата**: тир (справочник), живые статы
  (атака + здоровье), золотой, соплеменники на борде (`tribeMates`),
  свои копии (`copiesOwned`), цена покупки (`buyCostOf`). Признаки —
  кирпичи советника НАМЕРЕННО: вопрос замера — ПОРЯДОК (веса из данных
  против весов из правил), а не новые сигналы. Текстовых слагаемых
  у модели нет — это записанная бедность, см. «чего не докажет».
- **Парная гребневая регрессия**: разности признаков «куплен − не куплен»
  внутри инстанса, метка ±1 симметрично, `fitRidge` с λ=1 (интерсепт
  на симметричных данных нулевой сам). Счёт кандидата — линейный;
  топ-1 с детерминированным тай-брейком (zonePos, затем entityId).

## Оценка

- LOGO по партиям: модель для партии g обучена на инстансах остальных.
- **Hit инстанса — с честными ничьими**: кандидаты, разделившие максимум
  счёта (точным равенством — твины признаков дают его буквально),
  засчитываются ДОЛЕЙ купленных среди них. Целый hit при ничьей решал бы
  тай-брейк по позиции, а не модель (в 11 инстансах из 154 ничья
  разрезана меткой — 7% при пороге приёмки 5 п.п., молчать нельзя);
  урок cardstats «попал в любой максимум» здесь принимает форму
  ожидания — без подарка тай-брейку и без наказания за неразличимое.
  То же правило у бейзлайнов статов и тира; у советника выбор один.
- Метрика партии — средний hit по её инстансам; итог — среднее
  по партиям (кластер — партия, всегда). `D̄`, МРЭ и полоса считаются
  по партиям, у которых остался хотя бы один оценённый инстанс;
  фактическое их число печатается и входит в МРЭ.
- **Бейзлайны**: СОВЕТНИК (верхний buy-совет `adviseTavern` — главный
  соперник), random аналитический (доля кандидатов с купленной картой),
  наибольшие статы, наибольший тир.

## Критерий решения (зафиксирован заранее)

`D_g = hit_g(модель) − hit_g(советник)`, `D̄` — среднее по партиям.
Полоса sign-flip 10 000 перестановок, зерно `createRng(20260820)`;
МРЭ = 1.645 · SD(D_g)/√n.

**Достижимость порога — посчитана ДО прогона и только по бейзлайнам**
(урок cardstats №3; модель не запускалась, скрипт одноразовый). Советник
предсказывает покупку игрока в **70.3%** по партиям (до оверлея, part4–8:
72.6%; с оверлеем: 69.7%) — запас `1 − hit(советник)` равен **29.7 п.п.**,
порог 5 п.п. по запасу достижим с большим полем. Дисперсия: у грубых
прокси-моделей (статы, тир) SD парных разностей с советником 0.26–0.28,
то есть их МРЭ ≈ **9 п.п. — ВЫШЕ порога 5 п.п.** Модель, похожая
на советника сильнее прокси, даст меньшую дисперсию, но заранее это
не известно; записываем честно: если SD(D_g) модели окажется уровня
прокси, приёмку решает МРЭ, а не порог — тот же режим, что в замере 1.
Отдельно: hit(советник) до оверлея даже ВЫШЕ, чем с ним, — «петля
подражания советам» не выглядит главным механизмом совпадения (см. также
«чего не докажет», п.1).

- **ПРИНЯТЬ** (публикуется диагностика расхождений; дальнейшее
  использование — отдельный вопрос игроку): `D̄ ≥ +5 п.п.` И выше 95-го
  перцентиля полосы И выше МРЭ И среднее по партиям hit(модель) выше
  среднего по партиям hit(random) — сравнение СРЕДНИХ, одно чтение.
  5 п.п. — примерно один дополнительно угаданный ход из двадцати; ниже
  продуктово неинтересно.
- **ОТВЕРГНУТЬ** (как «на этих партиях советник предсказывает игрока
  не хуже модели» — о переносимости см. «чего не докажет», п.1):
  `D̄` ниже 5-го перцентиля полосы.
- **НЕ ДОКАЗАНО** — остальное; перезамер при +10 новых партиях.

## Проверки годности — до главных чисел

- **Отрицательный контроль конвейера**: метки заменяются на случайного
  кандидата — **K = 10 сеяных реализаций** из одного ГПСЧ
  (`createRng(20260821)`), полный LOGO на каждой. Одна реализация шумит
  на ±3 п.п., и порог был бы меньше двух её сигм; среднее по десяти
  сжимает шум втрое. Нуль — **аналитическое ожидание hit СОБСТВЕННОГО
  выбора модели** («куплена карта случайного кандидата»): сравнение
  с random смещено дублями карт в витрине, а с ожиданием собственного
  выбора нуль точный. Утечка — только ПОЛОЖИТЕЛЬНЫЙ средний разрыв
  больше 5 п.п. (модель хуже своего шанса — шум в безопасную сторону);
  тогда **прогон недействителен**. Печатаются среднее, минимум
  и максимум реализаций.
- **Детерминизм**: обучение без случайности, два прогона побайтно равны.

## Вторичное — печатается, но НЕ решает

- Hit статов и тира (те же инстансы).
- Обучение только на партиях мест 1–3 («имитация из побед», 11 партий) —
  та же LOGO-оценка на всех партиях.
- Разбивка D̄: партии ДО оверлея (part4–8, советов игрок не видел)
  против партий С ним.
- λ-свип {0, 1, 10}; веса модели на всех инстансах по именам признаков.
- Расхождения «модель ↔ советник» с фактическим выбором игрока —
  диагностика, ради которой замер и затевался: счёт «за модель /
  за советника / мимо обоих» и по пять примеров С КАЖДОЙ стороны
  (односторонняя печать была бы отбором доказательств).

## Чего этот замер не докажет

1. **Петля обратной связи — и она ДВУХКОНТУРНАЯ.** Первый контур:
   с part9 игрок играет С ОВЕРЛЕЕМ и может следовать советам. Второй,
   глубже: советник ДОРАБАТЫВАЛСЯ по этим же партиям — весь цикл
   «жалоба → фикстура → правка» (part9–part26) подгонял его к вкусам
   игрока на тех самых данных, на которых он здесь бейзлайн, то есть
   бейзлайн видел тест-сет. Оба контура завышают hit(советника), замер
   консервативен к ПРИНЯТЬ, а ОТВЕРГНУТЬ читается только как «на ЭТИХ
   партиях доведённый по ним же советник предсказывает не хуже» —
   переносимости у него нет. Предпрогонная разбивка намекает, что первый
   контур слаб (до оверлея hit советника даже выше), но партий «до»
   всего пять, и второй контур накрывает обе группы.
2. **«Выбор игрока» ≠ «лучший выбор».** Имитация меряет предсказуемость,
   а не качество: даже ПРИНЯТЬ не значит «советник играет хуже» — только
   «в выборе игрока есть система сверх советника».
3. **Шесть признаков бедны** против одиннадцати слагаемых советника
   с текстовым разбором: проигрыш модели читается и как «нечего ловить»,
   и как «нечем ловить». Обогащение признаков — только новой
   предрегистрацией.
4. **Эффективная выборка — 23 партии**, а не ~двести инстансов: точки
   одной партии зависимы, кластеризация по партиям везде.

**Предрегистрация написана 29.08.2026 ДО первого прогона основной ветки.**
Прибор (`src/ml/relativeFeatures.ts`, `npm run ml:eval3`) написан
и покрыт тестами на синтетике; на настоящих данных до коммита этого

## Вопрос

Несут ли признаки положения ПРОТИВ СТОЛА сигнал о финальном месте —
сверх таблицы лидеров (B1) и, главное, сверх её сжатия к среднему (B2)?
Второе — настоящий вопрос: B2 на 33 партиях уже впереди таблицы
на 0.283 места, и модель, которая «выиграет у таблицы» одним сжатием,
ничего нового о признаках не скажет (предобъявленное чтение замера 1).

## Данные

- Тот же загрузчик, дедуп и фильтр билда, что у замеров 1–2
  (`src/ml/dataset.ts`): на 29.08 — **33 партии, 395 точек решения**,
  все 33 с таблицей лобби во всех точках (проверено по данным: 8 игроков
  в каждой точке, здоровье прочитано у всех, свой `playerId` найден
  в таблице всюду, своё hp и место в таблице совпадают с состоянием).
- **Исключение:** партия, у которой таблица лобби пуста хотя бы в одной
  точке, исключается ЦЕЛИКОМ и называется в отчёте. Пустая таблица —
  не «неизвестно», а ложь для относительных признаков, а исключать
  точки внутри партии значило бы менять состав кластера. Сейчас
  таких партий 0; чужие записи старых сборок могут их принести.
- Целевая, места, скос к первым местам — как в замере 1 (среднее 3.73).

## Признаки — 5 штук, все с одной точки, все из `lobby` и `hero`

| # | признак | формула | пропуск → |
|---|---|---|---|
| 0 | текущее место | `finalPlace` — ТОТ ЖЕ признак, что у B2 | 4.5 |
| 1 | живых игроков | число игроков лобби с `health − damage + armor > 0`, включая себя | 8 |
| 2 | здоровье против живых | моё hp − среднее hp живых СОПЕРНИКОВ | 0 |
| 3 | тир против живых | мой тир − средний тир живых соперников (непрочитанный тир в среднее не входит) | 0 |
| 4 | место среди живых | `(место − 1) / (живых − 1)`, зажато в [0, 1] | по 8 живым |

Почему эти и почему без семи «своих». Признак 0 делает модель
«B2 плюс относительные»: выигрыш у B2 читается как сигнал именно
добавленных признаков. Признак 1 — сколько мест ещё разыгрывается;
признак 4 — взаимодействие «место × стадия», которого линейной модели
замера 1 не хватало (там она проигрывала таблице с 9-го хода таверны:
1.57 против 1.45 и 1.19 против 0.76 в поздних корзинах). Признаки 2–3 —
положение против стола, ради которого замер и делается. Семь абсолютных
признаков в основную ветку НЕ входят: замер 1 показал, что они не несут
сигнала и коллинеарны (ход таверны и лог-статы — одна пара); набор
«семь плюс четыре» печатается во вторичном.

Зажим у признака 4 — по фактуре: в 8 точках из 461 выбывший игрок ещё
стоит в таблице выше живых (снимок до пересчёта мест), и без зажима
«место среди живых» превысило бы единицу. Описательная статистика
на всех 395 точках (до прогона, без модели): живых 2…8 при среднем 6.92
(269 точек из 461 — при полном столе, замер тяжёл ранними ходами);
hp против живых −30…+23.8, среднее −1.05; тир против живых −1…+3,
среднее +0.17; место среди живых 0…1, среднее 0.53.

## Модель и оценка — как в замере 1, без изменений

Гребневая регрессия, λ = 1 на стандартизованных признаках, интерсепт без
штрафа, предсказание в [1, 8], пул точек с равным весом точки. LOGO
по партиям, MAE партии → среднее по партиям с равным весом партии.
Бейзлайны B0 (среднее место обучающих партий), B1 (текущее место), B2
(та же ridge на единственном признаке 0). Процедура одна и та же на оба
набора признаков — это один скрипт с параметром `--features`, и числа
замера 1 на нём воспроизводятся в точности (проверено 29.08; в выводе
изменился только заголовок ветки — он теперь называет замер).

## Критерий решения (зафиксирован заранее)

Два парных числа по партиям:
- `D_g = MAE_g(B1) − MAE_g(модель)`, `D̄` — среднее (продукт: строка
  в оверлее заменяет чтение таблицы);
- `D₂_g = MAE_g(B2) − MAE_g(модель)`, `D̄₂` — среднее (наука: признаки
  или сжатие).

У каждого — своя полоса sign-flip (10 000 перестановок, зёрна
`20260829` для D̄ и `20260831` для D̄₂) и своя МРЭ = 1.645 · SE.

- **ПРИНЯТЬ** — только всё сразу: четыре условия замера 1 для `D̄`
  (≥ 0.25 места; выше 95-го перцентиля полосы; выше МРЭ; MAE модели ниже
  MAE B0) **и** два для `D̄₂`: выше 95-го перцентиля своей полосы и выше
  своей МРЭ. Порога в местах у `D̄₂` нет намеренно: продуктовый порог
  уже стоит у `D̄`, а `D̄₂` отвечает на вопрос «признаки или сжатие»,
  у которого шкала — только шум.
- **ОТВЕРГНУТЬ** — `D̄` ниже 5-го перцентиля своей полосы (таблица знает
  не меньше) ИЛИ `D̄₂` ниже 5-го перцентиля своей (относительные признаки
  ХУЖЕ сжатия: модель с ними проигрывает модели без них).
- **НЕ ДОКАЗАНО** — остальное; умолчание — не вносить; перезамер
  при +10 партиях ИЛИ при первых чужих партиях без оверлея (тогда —
  отдельная предрегистрация для фильтра `overlay`).

Предобъявленные чтения — те же, что в замере 1: `D̄_late` (ходы таверны
≥ 5) ограничивает право на строку ранними ходами, если ПРИНЯТЬ достигнуто
при `D̄_late ≤ 0`. Отрицательный контроль на перемешанных местах
(зерно `20260830`), порог утечки +0.1 к B0 — прогон недействителен.
Детерминизм: два прогона побайтно равны.

## Достижимость — до прогона, только по бейзлайнам и модели замера 1

Урок №2 замера 1: SD парных разностей до прогона не известен, и порог
может оказаться ниже МРЭ. Прокси посчитаны 29.08 без единого запуска
относительной модели:

- **B2 против B1** (одни бейзлайны): `D̄ = 0.283`, SE 0.191, МРЭ-прокси
  0.314. То есть сжатие само почти берёт продуктовый порог 0.25, но не
  полосу и не МРЭ; чтобы модель прошла условия по `D̄`, ей надо обойти
  B2 примерно на 0.03 места — и это как раз `D̄₂`.
- **Модель замера 1 против B2** (масштаб разности двух похожих
  ridge-моделей — прокси SD(D₂)): `D̄₂ = −0.057`, SE 0.032, **МРЭ₂-прокси
  0.053**. Значит для ПРИНЯТЬ `D̄₂` должно быть порядка 0.06 и выше.
- **Где у B2 запас:** по корзинам (по точкам) `|B2 − финал|` 1.88 / 1.84 /
  1.48 / 1.40 против `|B1 − финал|` 2.83 / 2.29 / 1.46 / 0.79 (ходы 1–4 /
  5–8 / 9–12 / 13+, n = 124 / 124 / 109 / 38). Весь запас — в поздних
  корзинах: если относительные признаки лишь ДОГОНЯТ таблицу там, где
  она лучше сжатия (9–12 и 13+), выигрыш по точкам составит
  ≈ (0.02 × 109 + 0.61 × 38) / 395 ≈ 0.06 места — то есть **на уровне
  МРЭ₂-прокси, а не заведомо выше**. Критерий достижим, но без запаса;
  это записано заранее, чтобы «НЕ ДОКАЗАНО» при `D̄₂ ≈ 0.04` читалось
  как «выборка не разрешает», а не как «признаки пусты».

## Вторичное — печатается, но НЕ решает

- λ-свип {0, 0.3, 1, 3, 10}; нормировка внутри корзин ходов.
- Корзины ходов таверны: модель против B1 и B0 по точкам.
- **Семь «своих» плюс четыре относительных** (11 признаков, место один
  раз): MAE, `D̄`, `D̄₂` — добавляют ли абсолютные признаки что-нибудь
  к относительным.
- Веса модели на всех 33 партиях по именам признаков.

## Чего этот замер не докажет

1. Всё из замера 1: 33 партии одного игрока одного патча; селективность
   поздних корзин; зависимость точек одной партии (эффективная выборка
   33); прогноз не причинен.
2. **Таблица лобби в точке решения — снимок НАЧАЛА хода:** соперники
   свои ходы ещё не сыграли, их тир к бою может вырасти. Признаки
   относительны по столу, но не по времени.
3. **Признак «живых» и место среди живых частично уже знает B1** —

## Критерий решения — ДОСЛОВНО критерий замера 3

своей; НЕ ДОКАЗАНО — остальное. Зёрна: `20260901` (полоса D̄),

по трём замерам, тоже: относительные читают стадию, история — позднюю
корзину, и то и другое таблица почти знает сама.

Отсюда решение по дорожной карте (шаг 4 — ΔV-ранжирование действий —
требовал V, прошедшего свой критерий): **ветка V(состояние) на данных
одного игрока ПРИПАРКОВАНА.** Возобновлять её стоит не новым признаком,
а другими данными: чужие партии без оверлея от исполнителей
(docs/collector.md) принесут и разброс уровня игры, и разброс исходов,
которого у выборки одного сильного игрока нет (среднее место 3.73,
константа — грозный бейзлайн). Первый чужой архив — повод для
предрегистрации замера 5 с фильтром `overlay` и `contributor`
и с порогом утечки +0.05.

### Что сделано с результатом

- **В оверлей ничего не вносится.** Прибор остаётся: `npm run ml:eval4`,
  детерминирован, тесты держат признаки и запрет на будущее.
- Ветка прогноза места припаркована до чужих партий; в «Отложено
  сознательно» CLAUDE.md это записано как решение, а не как пауза.
- Уроки: (а) прокси-МРЭ ×1.5 — рабочая норма; (б) отрицательный
  контроль ужесточить до +0.05, когда признаков больше пяти;
  (в) признаки по истории на ранних точках — шум, и если их вносить
  снова, то с индикатором «истории нет» и окном не короче трёх боёв.
